# Architecture

Concise map of how Self Beauty is built and why. The product spec lives in
`docs/superpowers/specs/2026-09-05-self-beauty-design.md`; the design language in `docs/DESIGN_SYSTEM.md`;
the media pipeline in `docs/MEDIA.md`.

## Stack

| Concern       | Choice                                                                                                                | Why                                                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Framework     | Astro 7, `output: 'static'`, TypeScript strictest                                                                     | Static HTML for GitHub Pages, zero JS by default, first-class i18n routing and image service.                                         |
| Interactivity | Vanilla TypeScript modules (`src/scripts/*`) loaded via component `<script>` tags                                     | The public site needs a menu, a language menu, a lightbox, filters and an accessibility panel. None of that justifies a UI framework. |
| Styling       | Plain CSS with design tokens (`src/styles/tokens.css`), scoped component styles                                       | Logical properties give RTL for free; tokens keep the brand coherent; no utility framework to fight.                                  |
| Fonts         | System Arial stack, no web fonts                                                                                      | Client decision; covers all three scripts via OS fonts, zero font bytes.                                                              |
| Content       | Astro content collections (JSON + Zod)                                                                                | Typed, validated, editable without touching templates; the same shapes the admin will produce.                                        |
| Images        | Committed JPEG/PNG web masters in `src/assets/media`, AVIF/WebP `srcset`s generated by Astro's sharp service at build | Deterministic in CI; HEIC never reaches the build.                                                                                    |
| Video         | Committed H.264 MP4 tiers (720/480) + posters in `public/media/video`                                                 | Browsers cannot play the 10-bit HEVC phone sources. Poster-first, loads on demand.                                                    |
| Tests         | Vitest (unit), Playwright + axe (e2e, multi-viewport), `astro check`, ESLint, dist link checker                       | See "Verification".                                                                                                                   |
| CI/CD         | GitHub Actions: `ci.yml` (gates) and `deploy.yml` (Pages)                                                             | Official `actions/deploy-pages`; no secrets required.                                                                                 |

## Routing and i18n

```
/                      language gateway (meta refresh → /he/, JS honours sb:lang)
/he/…  /ru/…  /en/…    every page exists in all three locales
/404.html              trilingual not-found page (GitHub Pages picks it up)
/robots.txt            generated endpoint; sitemap URL is base-aware
/sitemap-index.xml     @astrojs/sitemap with hreflang alternates
```

- Pages live under `src/pages/[lang]/…` and use `getStaticPaths()` from `src/lib/paths.ts` (one path per locale).
- Copy comes from typed dictionaries: `src/i18n/he.ts` is the canonical shape; `ru.ts` and `en.ts` are typed as
  `Dictionary` (a widened `typeof he`) so a missing key is a compile error, and `tests/unit/i18n.test.ts`
  also verifies key parity, empty strings and `{placeholder}` parity.
- `<html lang dir>`, canonical, hreflang (+ `x-default` → Hebrew), Open Graph and JSON-LD are emitted by
  `src/layouts/Base.astro`.
- The language switcher links to the same page in the other locale; clicking it persists `sb:lang`.
  Preference is only stored on an explicit choice, never inferred, so shared links open in the language they were shared in.
- Base path: `astro.config.mjs` reads `SITE` and `BASE` from the environment. Internal links always go
  through `href()` / `localeHref()` in `src/lib/urls.ts`, so moving to a custom domain is a variable change.

## Data model

`src/content.config.ts` defines three collections:

- `puppies` — name/description per locale, breed, sex, status, ≤3 images (schema-enforced), optional video,
  `published`, `featured`, `demo`, `internalNote`. No price field exists by design.
- `litters` — breed, expected label per locale, optional parents, `published`, `demo`.
- `testimonials` — source language, full text in all three languages, neutral attribution, `demo`.

`demo: true` records are shown only in `astro dev` or when `SB_INCLUDE_DEMO=1`; production builds never
include them (`src/lib/listings.ts`). Titles for parents render only when `verified: true`.

`src/data/site.ts` holds business facts. Empty strings are deliberate TODOs (kennel club URL, owner display name).

`src/data/media.ts` is the media catalogue: id, localized alt/caption, focal point, chapter, breeds, real capture year.

## Components (public site)

```
layouts/Base.astro          head/meta/JSON-LD, skip link, Header, main, Footer, StickyContactBar, A11yPanel, Lightbox
components/Header.astro     sticky header, desktop nav, language menu, accessibility button, WhatsApp CTA, mobile sheet
components/LangSwitcher     menu (header) or inline (sheet/footer) variants
components/StickyContactBar two-segment Call / WhatsApp bar, mobile only, safe-area aware, hidden while dialogs are open
components/A11yPanel        <dialog>: text size ×1.125/×1.25, high contrast, reduce motion (persisted)
components/Picture          catalogue-aware <Picture>: AVIF/WebP/JPEG, widths+sizes, focal object-position
components/VideoTile        poster-first video; tier chosen at play time (480p on narrow viewports / Save-Data)
components/Lightbox         single <dialog> reused by all galleries; keyboard, swipe, RTL-aware arrows
components/GalleryGrid      uniform 4:5 grid, landscape tiles span 2 columns, surplus landscapes become full rows; filters; per-group lightbox
components/PuppyCard, StatusChip, BreedGrid, StoryExcerpt, LitterBanner, CtaBand, SectionHeading, Icon
```

## Accessibility model

Landmarks, one `h1` per page, skip link that focuses `main`, visible focus rings, ≥44px targets, labelled
icon buttons, native `<dialog>` for the panel and lightbox, `inert` on the page behind the mobile sheet,
`aria-live` counters, `prefers-reduced-motion` plus a site-level motion switch, and a trilingual accessibility
statement. axe runs on every page × locale in CI (`tests/e2e/a11y.spec.ts`); serious/critical violations fail the build.

## Verification

`npm run verify` = lint → `astro check` → unit tests → build → link check. `npm run test:e2e` runs Playwright
against `scripts/serve-dist.mjs` (a static server that mimics GitHub Pages: base path, trailing slashes, real 404 status, gzip), on 360/390/768/1440 device profiles plus the
`a11y` and `widths` projects (320–1440 px, overflow, tap-target and sticky-bar checks). `SHOTS=1` writes full-page screenshots.

## Deployment

`deploy.yml` runs the CI gates, builds with `SITE`/`BASE` from `actions/configure-pages` (project page) or
repository variables (custom domain), uploads `dist/` and deploys with `actions/deploy-pages`. No secrets.

## Admin (Part B, Lean V1)

- `src/pages/admin/index.astro` — standalone noindex page mounting the Preact app (`client:only`).
- `src/admin/` — `client.ts` (supabase-js, distinct storage key), `api.ts` (all data access under RLS; publish =
  copy public files then flip `published`; unpublish = flip then clean; add image = private → public → row; replace =
  new id), `image-pipeline.ts` (sniff → native decode / libheif fallback → orientation → 1600 & 640 JPEG),
  `App.tsx` (auth gate, hash routes `#/`, `#/archive`, `#/new`, `#/edit/<id>`), `ListingList`, `ListingForm`,
  `PhotoManager`, `StatusSheet`, `Toast`, `admin.css` (tokens, Arial, 44 px targets, bottom sheet).
- Public read path: `src/lib/public-listings.ts` (plain fetch, publishable key, 8 s timeout, row validation) →
  `LivePuppies.astro` (Astro renders the card `<template>`; `src/scripts/live-puppies.ts` clones it) and
  `/[lang]/puppies/view/` + `live-puppy-detail.ts`. Demo builds (`SB_INCLUDE_DEMO=1`) keep the static fixtures and the
  static detail route for layout review; production renders the live island.
- Backend: `supabase/migrations/20260906000000_lean_v1.sql` (enums, tables, explicit RLS, `is_admin()`,
  `reorder_images()`, public RPCs with a fixed key list, buckets, per-bucket storage policies). Rationale and the
  review outcome: `docs/superpowers/specs/2026-09-06-admin-supabase-design.md`.
